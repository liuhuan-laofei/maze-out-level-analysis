方法与说明

数据怎么来的

  1. 来源：Maze+Out!+-+Tap+Puzzle_909_APKPure.xapk，包名 com.grandgames.arrowjam，Unity 6000.2.6f2（IL2CPP）。
  2. 关卡以 JSON 文本形式存放在 Unity 的 TextAsset 里，结构为 {itemModels[], width, height, difficulty, durationInSec, levelKind}。脚本流式读取 apk，不修改任何文件，共解析出 760 份，无失败。
  3. 每套关卡集的 LevelsConfig* 配置里有 difficulty 与 durationInSeconds，按 levelId 对应到关卡。October_2026 没有这份配置。
  4. 包里还登记了 arrows-only/level_N、tier1/2/3、270226_c 等资源路径，但这些资源文件不在包内，因此无法纳入。线上关卡由远程配置（RemoteLevelsConfig）下发，也不在本文档范围。

主线编号的拼接

1–300：21.10_Levels_1-300_fix；301–500：2205-arrows-main；501–700：07.11_Loop_Fixes；701–730：2904-arrows-loop_v2；731–760：October_2026。这个顺序是约定，不代表游戏内的真实顺序，也不代表上线时间顺序。

元素含义（推断）

kind名称依据置信度
1箭头 Arrow有 direction，路径末格为头部（末两格的位移与 direction 完全吻合，6 万条无例外）高
2箱子 Box矩形多格、带 health，层级与箭头同级中
3管道 Pipe路径形、带 health 和 passes（通过点）中
4拐角 Corner单格、带 direction1/direction2 和 demand中
8束带 Band全部落在箭头占用格上，且横跨 2–5 条不同箭头中
11钥匙 Key全部落在单条箭头的一个格子上；137 个含锁定幕布的关卡里，128 关的钥匙数与锁定幕布 health 总和完全相等较高
12幕布 Curtainlayer 1、带嵌套 items；嵌套箭头与顶层箭头在同一批格子上重叠，故按「垫在下层」绘制中
18锁定幕布 Lockedlayer 8、带 health 与 order；health 总和与同关 kind 11 数量在 128/137 关里完全相等较高

名称来自包内元数据里的物品类名（Pipe、Corner、Band、CurtainKey、LockedCurtain、Curtain、Box 等），但枚举数值和类名之间没有直接对照表，所以上表是按数据结构配对推断的，不是官方定义。「束带 / 管道 / 拐角」的真实玩法尚未经游戏内验证。

求解器与「依赖深度」

  • 规则：箭头点击后沿头部方向直线飞出棋盘；射线上如果还有其他未移除箭头的格子，就被挡住。
  • 每条箭头的「阻挡集合」= 射线经过的其他箭头。按轮次反复移除没有阻挡的箭头，轮数就是依赖深度（依赖链最长的一条）。
  • 幕布内的嵌套箭头按第二阶段计算（nested_depth），主文档里的深度只含顶层箭头。
  • 校验：375 个纯箭头关全部可以完全清空，说明基础规则的推断是对的。
  • 局限：含箱子、管道、拐角、束带等特殊元素的关卡，其真实规则本求解器没有建模。其中有 57 关在仅箭头规则下卡死，它们的深度只是下限，图表里用空心点标出。
  • 深度只衡量依赖结构，不等于玩家体感难度（没有考虑视觉遮挡、误触惩罚、倒计时、道具等）。

自绘截图说明

图片按每关 JSON 绘制：y 轴向上（与 Unity 一致），箭头头部为路径末格；颜色按 colorId 映射到一套示意色板，不是游戏里的实际配色。幕布在图里以淡紫色区域加较细的紫色箭头表示，锁定幕布以淡红色区域加数字徽标表示。
